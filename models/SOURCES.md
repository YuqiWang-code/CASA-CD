# Sources

CASA-Pyramid uses native MobileNetV2 feature extraction adapted from [WDMF-Net](https://github.com/LYT-Works/WDMF-Net), reference revision `453c5493b2aab88c908ced9135b677285059ec70`. Core reference code remains in `others/WDMF-Net`. The backbone ends at the 320-channel feature. TAR performs temporal fusion and channel projection; DCR provides foldable decoding. Their structural reparameterization follows the project's retained `others/STR-RepNet` reference.

The working hyperbolic context follows [task-calibrated geometry](HYPERBOLIC_DESIGN.md): 224 class-conditioned prototypes, one 32-dimensional Lorentz space, pooled-content keys/values, supervised class retrieval and an independent correction gate. The Euclidean context retains the [Run5 design](../docs/temporary/CASA-Pyramid_Run5_design.md), with 224 tokens and four 16-dimensional heads. Both preserve every TAR query. Historical Run5 checkpoints use the archived Run5 implementation. The complete-query/compressed-KV arrangement refers to [SAT](https://arxiv.org/abs/2604.07994), whose author repository identifies it as CVPR 2026 Findings. [Object-Contextual Representations for Semantic Segmentation](https://www.ecva.net/papers/eccv_2020/papers_ECCV/papers/123510171.pdf) provides earlier background for supervised soft-region aggregation.

`euclidean_context.py` implements squared Euclidean retrieval with shared query/key projection and pooling before key/value projection. `pyramid_context.py` defines class-confidence priors, source-count correction, Euclidean values, query-relative content updates and shallow depthwise local refinement. These compression and readout choices are the project's design, not unchanged components of SAT or OCR.

`hyperbolic_context.py` and `lorentz_ops.py` use curvature−1 Lorentz coordinates. The spatial lift reconstructs time as `sqrt(1+||z||²)`; [Hypformer, KDD2024](https://arxiv.org/abs/2407.01290) provides background for this parameterization. The working model lifts shared query/key projections divided by the square root of their width; intrinsic radius is `asinh(||z||)`. Keys are lifted from the same pooled content used by Euclidean values. They are not Lorentz centroids or geodesic Fréchet means. The supervised retrieval evidence and independent content gate are project designs, not unchanged components of Hypformer. [Law et al., ICML2019](https://proceedings.mlr.press/v97/law19a.html) distinguishes the closed-form squared-Lorentzian centroid used in historical models from a squared-geodesic center.

[The Numerical Stability of Hyperbolic Representation Learning, ICML 2023](https://proceedings.mlr.press/v202/mishne23a.html) and [Robust Hyperbolic Learning with Curvature-Aware Optimization, NeurIPS 2025](https://papers.nips.cc/paper_files/paper/2025/hash/75817c38dd91ccef8add921b2eb4284a-Abstract-Conference.html) inform representable radii and geometric consistency. CASA keeps fixed curvature and Euclidean trainable parameters; it does not use the latter paper's Riemannian AdamW. [Deep Change Monitoring, CVPR 2025](https://arxiv.org/abs/2503.00643) remains task-related evidence for hyperbolic representation in fine-grained tree change detection, without establishing gains for CASA's four datasets.

[Frequency-Aware Feature Fusion for Dense Image Prediction, TPAMI 2024](https://doi.org/10.1109/TPAMI.2024.3449959) distinguishes intra-category inconsistency from missing boundary detail. It motivates evaluating local detail separately from global context. CASA's average-filter residual and depthwise/pointwise refinement are not a reproduction of FreqFusion's adaptive filters or offsets. [Change3D, CVPR 2025](https://openaccess.thecvf.com/content/CVPR2025/html/Zhu_Change3D_Revisiting_Change_Detection_and_Captioning_from_A_Video_Modeling_CVPR_2025_paper.html) provides context for allocating lightweight capacity to change-related representations; CASA retains its Siamese backbone.

Historical Run5 uses protocol `casa_pyramid_40k_selective_selfref_v5`: a 1.0 learning-rate multiplier for the pretrained backbone, four main segmentation losses, and guide supervision with coefficient 0.2. There is no boundary auxiliary loss. All context convolution/linear weights use a separate parameter group with `decoupled_weight_decay=True` and weight decay 1e−4. Encoder and body groups retain coupled Adam L2 decay at 1e−4; other context parameters use zero decay. The implementation uses the per-group settings of [PyTorch 2.14 Adam](https://docs.pytorch.org/docs/2.14/generated/torch.optim.Adam.html), matching the server version. These settings support matched comparison of CTRL, Euclidean and hyperbolic variants, and are not claimed geometric innovations. Run5 used six full LEVIR probe epochs and four full SYSU probe epochs with validation evaluation; probes are not formal results and do not initialize formal training.

The [official ChangeMamba implementation from June 2024](https://github.com/ChenHongruixuan/ChangeMamba/blob/72597fa4a1fde0bffa94c94302a6dc848898be13/changedetection/script/train_MambaBCD.py#L115-L131) evaluates test every 500 steps and selects by Kappa. CASA-Pyramid Run2–Run5 evaluate every epoch and select by F1. Their final evaluation is test-selected, not an independent held-out evaluation. Earlier validation-selected results retain their original protocol labels. Actual training source and configurations are archived for each round.

Locally archived papers and official links are listed in the [literature index](../docs/参考文献/文献索引.md); the [Run4 research notes](../docs/参考文献/Run4_压缩与双曲检索/README.md) specify the evidence and its scope.

Run5 sharpens within-region class membership by squaring before normalization and uses its weighted posterior second moment as class support. Each dense query contributes its own key/value to the attention denominator, allowing compressed context adoption below one. The relative update is the weighted sum of prototype-minus-query values. These choices are grounded in the archived Run4 validation interventions and are project-specific, with no additional learned parameters.

[TransNeXt, CVPR 2024](https://arxiv.org/html/2311.17132v3), section 3.1.1, provides precedent for local and pooled candidates competing through the same softmax. The [retained official reference](../others/TransNeXt/README.md) contains the native attention implementation and Apache-2.0 license. Historical Run5 uses one self candidate with metric scores; the working hyperbolic candidate uses an independent content gate. [STViT, CVPR 2023](https://arxiv.org/html/2211.11167v2) informs content association in compression. [Learning Visual Hierarchies in Hyperbolic Space for Image Retrieval, ICCV 2025](https://arxiv.org/html/2411.17490v2) establishes task-grounded hierarchies; CASA does not infer semantic hierarchy solely from pyramid scales. [Run5 literature notes](../docs/参考文献/Run5_原型选择与自参照检索/README.md) record publication versions and scope.


The Run7 protocol is `casa_pyramid_40k_retrieval_v7`; optimizer and augmentation retain the common settings. Hyperbolic training uses 0.1 guide BCE plus 0.1 class-retrieval BCE; CTRL and the retained Euclidean model use 0.2 guide BCE. [OCR, ECCV2020](https://www.ecva.net/papers/eccv_2020/papers_ECCV/papers/123510171.pdf) informs supervised region aggregation. The candidate does not add temporal correspondence evidence, and does not claim semantic hierarchy or demonstrated accuracy gains from hyperbolic radii. Focused source papers are archived in [task geometry references](../docs/参考文献/双曲任务校准/README.md).

Run8 follows the staged [Run7 diagnosis and proposal](../docs/temporary/CASA_Pyramid_Run7_深度分析_调研与改进方案.md). Its first phase isolates retrieval-BCE weight on SYSU/WHU. Matched Euclidean retrieval and a single within-region cosine reweighting are implemented as controlled follow-up configurations; beta zero preserves the original compression exactly. Region refinement follows the project equation, without importing a full super-token backbone.
