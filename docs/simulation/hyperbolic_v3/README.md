## c2b：修正了什么

| v2 的问题（方案 §2 A1/A2 点名） | v3 的做法 |
|---|---|
| 范数按"整场景"统计（`P(:,:)` 把后两维合并） | 逐 token `‖z‖`，并报中位/CV/最小最大 |

## c2b 结果（`results/log_c2b.txt`，`res_c2b.mat`，`figures/fig_c2b_01_retrieval.png`）

**排序几乎一致，但注意力与 V 输出差别明显——这是 v2 没看到的部分。**

κ=0.20（实测 CV 附近）时，测地相对欧氏(z) 的三个差异量：

| 半径档 | 1−Spearman | JS 距离 | V 聚合相对误差 | top1 一致率 |
|---|---|---|---|---|
| V1 档 (0.47/0.345) | 6e-4 | 0.0094 | 0.012 | 0.930 |
| 实测档 (0.79/0.86) | 4e-3 | 0.133 | 0.220 | 0.882 |

- κ=0 时同样成立：V1 档 JS=0.0060 / Vrel=0.011，实测档 JS=0.110 / Vrel=0.226。
- 也就是说：在真实半径区间，**"排序不变"不等于"算子不变"**——注意力权重与 V 聚合
  会差 13%–22%，而 v2 用 0.006 的 JS 得出"几何不重要"的结论，是因为半径档取错了。
- 逐 token 保范归一化（把每个 token 拉回目标半径）是比换几何更大的干预：
  实测档下 top1 一致率掉到 0.43–0.54、JS 0.10–0.21。
- 类正确率本身对几何不敏感（0.96–0.99），所以**不能靠检索命中率判断几何是否有用**，
  必须看 JS / V 聚合 / 下游。

四档先验（`+类先验` 用真实类占比，`+尺度计数偏置` = −log N_s）：

| p | 距离 only | +类先验 | +尺度偏置 | +both |
|---|---|---|---|---|
| 1% | 0.993 | 0.993 | 0.993 | 0.993 |
| 5% | 0.777 | **0.958** | 0.782 | **0.958** |
| 10% | 0.818 | **0.892** | 0.825 | **0.892** |
| 20% | 0.745 | **0.835** | 0.725 | **0.835** |
| 50% | 0.487 | 0.527 | 0.547 | 0.540 |

- 类先验只在类别不平衡时有用（p≤20%），平衡时几乎无效；这与模块里 `support` 的作用面一致。
- **尺度计数偏置 −log N_s 会把尺度正确率从 1.000 压到 0.725**：它按尺度大小做偏置，
  在"查询确实来自某尺度"的任务里是纯损失。模块的 `source_bias` 含同一项，
  值得在 S9 的 B4/B6 里单独查（本仿真只说明它有代价，不说明真实模型里它错）。
