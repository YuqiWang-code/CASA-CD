## 1. A1：距离评分与温度（c2c 修正）

V3 的 c2b 有两个硬错：`geo` 用负距离、`euc_z` 用负平方距离、且没有实际温度；`geo_norm`
把目标范数又乘了 `sqrt(d)`（输入已是缩放后的 `z`）。c2c 全部改成与模型一致：

```matlab
DH2 = S.lorentz_dist(S.lift(zQ), S.lift(zK)).^2;   % 平方测地
DE2 = S.euc_sqdist(zQ, zK);                        % 同 z 的平方欧氏
LH  = -DH2 / (2*tau^2);  LE = -DE2 / (2*tau^2);    % tau = FROZEN_TAU = 0.4696
zQn = zQ ./ max(vecnorm(zQ,2,2),1e-12) * sinh(rhoQ_target);  % 不再乘 sqrt(d)
```

其它口径：场景/方向/基础噪声/逐 token 径向扰动跨半径档与 κ **共用**；κ 是同一批标准正态乘子
的幅度；半径档取真实 S7 的 Q 均值（SYSU 0.971/0.871/0.891/0.940，LEVIR 0.933/1.131/1.167/1.222），
K 半径由 S7 的 K/Q 保留比换算并**在名字里注明**（不是独立实测）；V 用独立值向量，不用键方向冒充。

### 结果（5 场景 × 200 查询 × 224 键；均值）

| 半径档 | κ | top-1 一致 | JS 距离 | 逐查询 Spearman | V 相对 RMS | 温度+行偏置残差 / logit 跨度 |
|---|---:|---:|---:|---:|---:|---:|
| S7-SYSU2334 | 0 | 0.973 | 0.0562 | 0.9949 | 0.170 | 0.009 |
| S7-SYSU2334 | 0.2 | 0.801 | 0.0681 | 0.9908 | 0.249 | 0.053 |
| S7-SYSU2334 | 0.8 | 0.669 | 0.1384 | 0.9540 | 2.62 | 0.135 |
| S7-LEVIR2334 | 0 | 0.899 | 0.1069 | 0.9925 | 0.386 | 0.020 |
| S7-LEVIR2334 | 0.8 | 0.581 | 0.1864 | 0.9390 | 2.93 | 0.132 |
| EQUAL（0.49） | 0 | 1.000 | 0.0056 | 0.9955 | 0.016 | 0.002 |

读法：
1. **排序不是零差异**：真实半径档下 top-1 一致率 0.90–0.97、Spearman 0.99 以上，但 JS 距离
   0.056–0.107、V 相对差 0.17–0.39。V3 说"排序一致 ⇒ 注意力不变"在数量上不成立。
2. **差异的主体是一个距离尺度因子**：单个温度 + 逐行偏置能把 logit 差压到跨度的 0.9%–2.0%；
   半径拉大（κ ≥ 0.4）后残余升到 13%，才不再是纯重标定。
   ⇒ 因此"几何是否有用"在真实模型上等价于问"τ 是否按几何标定"——这正是 S9a 的拟合温度臂要测的。
3. EQUAL 档几乎无差异（JS 0.0056、V 0.016），说明差异确实由半径分布驱动，与 V3 的
   `A=||Σw u||`、`ρ_pool=atanh(A tanh ρ)` 分析一致。
4. 保范重标（`geo_norm` 用正确写法）与测地的 JS = 0.0000：在同目标半径下两者等价，
   V3 里"约 22%"来自错误缩放，已失效。

## 2. A2：先验扫描（每 p 重新生成特征与标签）

V3 的错：每个 p 重新抽 `clsQ/clsK`，却沿用上一档半径的 `zQ/zK`，标签与特征不对应；只有欧氏；
未做 dev 选 λ。c2c 改成：每个 (p, 场景) **独立生成**键/查询/标签；四档先验
（distance only / +类先验 / +尺度计数偏置 / +both）× geo 与 euc；查询集平衡（一半变化一半背景）。

| p | 几何 | 距离 only | +类先验 | +计数偏置 | +both | +类先验 变化召回 | AP |
|---:|---|---:|---:|---:|---:|---:|---:|
| 1% | geo | 0.560 | 0.500 | 0.560 | 0.500 | 0.000 | 1.000 |
| 1% | euc | 0.588 | 0.500 | 0.588 | 0.500 | 0.000 | 1.000 |
| 10% | geo | 0.572 | 0.500 | 0.572 | 0.500 | 0.000 | 1.000 |
| 10% | euc | 0.648 | 0.500 | 0.648 | 0.500 | 0.000 | 1.000 |
| 50% | geo | 0.656 | 0.656 | 0.656 | 0.656 | 0.312 | 1.000 |
| 50% | euc | 0.728 | 0.728 | 0.728 | 0.728 | 0.456 | 1.000 |

（数字 = 平衡准确率 = (变化召回 + 背景召回)/2。）

结论与限制：
1. **类先验只改判决阈值，不改排序**：AP 恒为 1.000（该合成任务里排序本就可分），
   加先验后 p ≤ 20% 时把判决全部推到背景（平衡准确率 0.5、变化召回 0）。
   ⇒ V3 的"λ 总被选成 0"不能解释成"先验无用"，只能说明当时的臂没有 dev 校准；
   λ 必须用 dev 选、eval 只评价（S13a-1 的真实反事实才是判据）。
2. **尺度计数偏置在同一尺度内是常数**，因此对同尺度类判决零作用（0.560 vs 0.560）；
   它只改跨尺度竞争。把它与"类先验"混在一起（`+both`）会掩盖这一点。
3. 该段是**合成 sanity**：AP=1 说明任务太容易，不能据此判断真实先验收益；
   真实结论由 S13a-1 / S9 给出。

## 3. S13a-0：confidence support 梯度阻断（已复现）

`tools/simulation/s13_support.py` 逐字对照 `manifold_context.support_term` 复现：

| 臂 | support 范围 | support_head.weight 梯度范数 | 非零元素 |
|---|---|---:|---:|
| confidence + 零初始化（现状） | [1.000e-06, 1.000e-06] | **0.000e+00** | 0 |
| confidence + kaiming 初始化 | [4.8e-03, 3.6e-01] | 3.93 | 128 |
| share（无 abs）+ 零初始化 | [0.500, 0.500] | 2.77 | 128 |
| logsigmoid + 零初始化（候选修复） | [-0.693, -0.693] | 5.54 | 128 |

机制：零初始化 → `sigmoid=0.5` → `|2·0.5−1| = 0` → `clamp_min(1e-6)`；
`abs` 在 0 处次梯度为 0、`clamp` 在边界上梯度也为 0，两条路径同时断。
第 3 行证明断点来自 `abs+clamp` 而不是零初始化本身；第 4 行给出中性初始化下仍有导数的候选。
**边界**：梯度为 0 只说明该头学不到东西，不能推出"先验对任务无用"——那要 S13a-1。
另外 S7 里 `min=1e-6, max=0.0` 的四舍五入不一致也应从原始精度重取，不能据此说"严格恒定"。
