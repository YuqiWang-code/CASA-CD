## 1. 项目定位与硬约束

- 任务：高分辨率遥感**二值变化检测**（全监督），4 数据集：CDD / LEVIR / SYSU / WHU
  （A/B/label + list/*.txt，label 阈值 `gray>=128`，256×256）。
- 目标：**极轻量**（有效推理参数 `<3M`，工程目标 ≤2.20M），F1/IoU 在极低参数量等级
  超过轻量 SOTA（对标 RFANet 2.86M / SeCoR 2.50M / Lighter 1.10M / CGLNet 0.99M）。
- 约束（反复强调，不要违反）：
  - 方法创新导向；**不改 loss、不把训练技巧当创新**；单 seed=16（不做多 seed）；
  - 每个实验**唯一变量** + **预注册 gate**，gate 不过不进入下一步，不做 sweep；
  - 不把量化/剪枝/蒸馏当核心贡献；不做防御性编程。
- 训练协议固定：BCE+Dice、Adam(lr=2e-4, betas=(0.9,0.99), wd=1e-4)、poly(power 0.9)
  +200 iter warmup、`max_steps=80000`、batch 16、256×256、seed 16、**test-as-val**
  （每 epoch 在 test 上挑 best；epoch 0 后跳过一次评估，官方行为）。

## 3. 实验史与全部正式结果

> 正式数字只认 `train_log.txt` 最后一个完整 `=== TEST RESULTS === ... === END TEST RESULTS ===`
> 区块；不以 checkpoint 文件名 / epoch 行 / Excel 为准（Excel 只做汇总）。

### 3.1 Baseline Run1（官方协议复现，已完成）

| 数据集 | F1 | IoU | 备注 |
|---|---:|---:|---|
| CDD | 97.75 | 95.60 | 官方未评测 |
| LEVIR | 91.95 | 85.10 | 官方 91.81，+0.14 |
| SYSU | 82.48 | 70.19 | 官方未评测 |
| WHU | 94.84 | 90.18 | 官方 94.53，+0.31 |

复杂度：TOTAL 20.661M / EFFECTIVE 11.754M（ResNet layer4+fc 死参数 8.907M）/ FLOPs 26.32G。
**⚠️ 勘误**：官方协议会把 ViT 训练成**精确零权重**（~1600 steps 内 pos_embed 4.43→0.0007，
Adam 小梯度全步长 + 归零后梯度消失的吸收态）——LEVIR/CDD/WHU 的 baseline 数字全部来自
「死 ViT」模型，SYSU 仅 best 检查点健康。**任何可训练 ViT 的实验都必须先过冻结/健康 gate。**

### 3.2 CASAA（创新主线一，已按预注册规则终止）

| Run | 内容 | 结果 |
|---|---|---|
| Run1 | Paired Late-Stage CASAA（blocks 8-11，K=64=Kc32+Kb32）；A1 content 对照、A2 cosine 主方法 | LEVIR 受死 ViT 污染作废；SYSU：A1 82.50 / A2 82.35 |
| Run2 | 冻结 ViT + Oracle 机制诊断（GT occupancy 路由，DIAGNOSTIC-ONLY） | A1 82.04；**Oracle 83.52（+1.48）**→ 机制有 headroom，瓶颈在可部署 signal |
| Run3 | Router Audit（cosine Spearman 0.23-0.29 弱）+ A4-D detail-only 救援 run | fused 未过 gate；detail-only ranking 明显更好但 **F1 81.92（vs A1 82.04，−0.12）→ 失败** |

证据链（SYSU，相对 A1）：ranking Top32 precision 0.39→−0.15；0.63→−0.12；1.0(oracle)→+1.48。
**结论：可部署 change signal 救不回机制收益 → 停止 router 迭代。** 留存：A1 的
「Full-Q + K=64 content 压缩基本无损」作论文 analysis/ablation，不作主贡献。

### 3.3 主线二 Run4（当前，SYSU 先行，全部冻结 ViT + corrected DeiT loader）

| Run | 结构变化 | F1 | IoU | Params | FLOPs | Gate |
|---|---|---:|---:|---:|---:|---|
| R4-0 A0_FULL12_FROZEN | 健康 full12 冻结参考 | **83.14** | 71.14 | 11.754M | 26.32G | 参考 |
| R4-1 VIT4_OLDHEAD | ViT depth 12→4 | 82.77 | 70.61 | 8.195M | 24.10G | **通过**（ΔF1 −0.37 ≥ −0.50） |
| R4-2 VIT4_LIGHTDETAIL | ResNet C2-C4 → LightDetail 32/64/128（0.037M）+ 1×1 adapters | 82.30 | 69.92 | 5.492M | 10.73G | **未过**（ΔF1 −0.47 > −0.30） |
| R4-2b LIGHTDETAIL48 | 预注册容量 fallback 48/96/160（0.065M） | 82.32 | 69.95 | 5.533M | 10.98G | **未过**（ΔF1 −0.45） |

关键事实：① 4-block 冻结 prefix（82.77）已超过 trained baseline（82.48）与全部 CASAA
冻结模型；② corrected loader 的健康 full12 参考 = **83.14**（新基线，替换 Run1 的 82.48 用法）；
③ LightDetail 省 2.7M 参数、55% FLOPs，但稳定掉 ~0.45 F1；④ 容量 bump 只 +0.02（噪声内）
→ 不像纯容量问题；⑤ 预注册 fallback 已耗尽（文档规定不再做宽度 sweep）。

## 7. 关键坑与约定（血泪清单）

1. **ViT 训练崩溃**：绝不直接用统一 lr=2e-4 训练 DeiT（会训成零权重，吸收态不可恢复）；
   一律 `--freeze_vit 1`；必须解冻时先跑 2K-step health gate（`vit_lr_ratio 0.1`，
   监控 pos/patch/qkv norm 比值 ≥0.8），通过才允许一次 80K。
2. **Corrected DeiT loader**（Run4 起）：patch_embed 原位加载；pos_embed 去 cls/dist
   token 后 14×14→16×16 bicubic；`--vit_depth 4` 时 blocks.4-11 必须**不存在**于
   state_dict（不是 requires_grad=False）。R4-0 的 83.14 才是健康参考。
3. **参数量口径**：effective = forward 图内全部参数（冻结照计、dead 不计）；
   当前 depth4+light 组合 5.49M，最终 UL 目标 ≤2.20M。
4. **FLOPs 口径**：双时相 2×3×256×256；fvcore 对 argsort/topk 等动态 op 计数不全，
   必须同时报 unsupported_ops；不要拿 26.32→26.09 这种 1% 差异包装加速。
5. **Oracle 路由是 DIAGNOSTIC-ONLY**：训练/测试用 GT，日志已标
   `[DIAGNOSTIC-ONLY] oracle routing uses GT and is not deployable`，绝不作方法结果。
6. **PowerShell 引号**：`_ssh.py` 直接传含引号/管道的命令会被吃引号 → 一律用文件模式。
7. **pkill 自杀匹配**：`pkill -f 'train.py'` 会杀掉正在执行这条命令的 shell →
   用 `pkill -f '[t]rain.py'`。
8. **单任务纪律**：一张卡最多一个训练；多任务/重复启动会 OOM 互杀 + 损坏 checkpoint。
9. **.sh 必须 LF**：Windows 下任何脚本写完用字节扫描确认无 CRLF。
10. **epoch 0 后跳过一次评估**是 ChangeViT 官方行为；`last.pth` 含优化器需
    `weights_only=False` 加载（已处理）。
11. **eval 架构参数必须与训练一致**（mode/router/vit_depth/detail_mode），
    CASAA 零参数下错配会静默跑错结构。
12. **rounds/时间管理**：SYSU 一个 80K 约 3-4.5h（103-145s/epoch × 107），
    LEVIR ~4.4h（85-90s × 180）；跑实验前先查 `nvidia-smi` 确认 GPU1 空闲。
