# 0. 结论先行

现在对你的研究路线可以做一个更准确的归位：

> **《时空变化高效建模.docx》就是这一整条课题的原始“母方案”。**
>
> - 第一部分“时空结构重参数”后来发展成了 `STR-RepNet`：时相 `Concat + Sum + signed-Diff` 的可折叠建模，加上空间/跨尺度重参数化解码；
> - 第二部分“非对称、变化感知 token”就是现在 CASA-CD 第一创新点 CASAA 的原始方向：**Full Query + Compressed K/V，变化 token 保留、稳定背景聚合**。
>
> 因此 CASA-CD 最终论文最自然的结构，不应再是 `TASS + STR`，而应重新回到导师原始设计的两条主线：
>
> **创新 1：CASAA —— 编码器内部的变化感知非对称 Token 建模。**  
> **创新 2：STR —— 多尺度挑层连接与解码阶段的时空结构重参数化。**

《时空变化高效建模》第一页已经明确写出三类时相分支：拼接、求和、差分；第二页进一步把空间异构训练分支解释为大范围、局部、空洞、横向/纵向和恒等分支；部署图则收敛为 `Concat → 1×1 Conv → DWConv → 1×1 Conv`。文档最后又直接给出“完整 Query、压缩 KV；保留变化查询位置、压缩双时相冗余背景”的 Change-Aware SAA 方向。也就是说，这两个创新本来就是一个统一故事，而不是两个后来硬拼的模块。

**但在你开始按上一版方案改代码之前，我建议先修正 7 个关键点。** 其中前 5 个属于 P0/P1，若不修正，很容易出现“代码能跑，但实验归因是错的”。

1. **SHViT-S1 的真实尺度结构和上一版文档中的描述不完全一致。**
2. **CASAA 放在 1/16 时，不能声称“继承 SHViT 原有 QKV 预训练权重”。**
3. **当前 CASA-CD 的 poly LR 调度器会把 backbone LR ratio 覆盖掉；如果不改，`0.1× backbone LR` 实际不会生效。**
4. **当前数据管线 `ToTensor()` 会把 6 通道整体反转，从而把 A/B 时相也交换；必须先决定是否保持该协议，不能无意中改。**
5. **CASAA 的动态 routing FLOPs 不能只靠 fvcore，也不能只写 `O(NK)`；聚类/TopK/assignment 本身也有推理开销。**
6. **上一版 5 组消融缺少“STR-only”组；如果论文有两个创新点，最小完整消融应该是 2×2 主效应 + CASAA 机制对照，共 6 个变体。**
7. **SHViT-S1 仍然只是“第一优先候选 backbone”，不是在跑完 A0×4 前就已经成为最终 backbone。**

下面逐项展开。

# 1. 先把导师原始文档与两个仓库的关系固定下来

## 1.1 导师文档第一部分 → STR-RepNet

导师文档对“时相结构重参数化”的原始定义是：

\[
Y_c = BN_c(W_c * [X_1,X_2])
\]

\[
Y_s = BN_s(W_s * (X_1+X_2))
\]

\[
Y_d = BN_d(W_d * (X_2-X_1))
\]

其中：

- concat：学习一般跨时相通道关系；
- sum：强化稳定背景/共享结构；
- signed diff：强化变化方向和变化响应。

这正是 STR-RepNet 当前 `TemporalRep1x1` 的核心：

```python
y = BNc(Conv([P,Q]))
y += BNs(Conv(P+Q))
y += BNd(Conv(Q-P))
```

部署时解析折叠为：

\[
W_P=W_{c,P}+W_s-W_d
\]

\[
W_Q=W_{c,Q}+W_s+W_d
\]

最终只有：

```text
Concat(P,Q) -> single 1×1 Conv
```

这里要坚持一个论文表述原则：

> STR 的价值不是“部署阶段多了更多函数能力”，而是**训练阶段通过有明确变化先验的多分支参数化改善优化路径，部署阶段又能无损折叠回单路径。**

不要写成“sum/diff 分支在部署时仍然额外存在”。它们已经被吸收进等价卷积权重。

---

## 1.2 导师文档第二部分 → CASAA

导师文档最后两页已经明确写了：

```text
SAT: Selective Aggregation Transformer
完整 Query、压缩 KV
高分辨率遥感 token 很多，但变化区域少
不能粗暴下采样，否则小目标/窄道路/边界会丢
保留完整变化查询位置
压缩双时相冗余背景信息
设计 Change-Aware SAA
```

所以 CASA-CD 第一创新点的论文主张应固定为：

> **保留完整的空间 Query lattice，不删除最终需要逐位置判别的位置；只对提供上下文的 K/V 做双时相变化条件下的选择性构造。变化候选尽量保留为独立上下文 token，稳定背景进行强聚合。**

真正区别于普通 SRA / pooling / token pruning 的关键词是：

```text
bi-temporal
change-conditioned
full spatial queries
selective context construction
stable-background aggregation
```

不能只写“KV 压缩”，因为这不是充分的新颖性。

# 2. P0：必须先修正上一版方案里的 SHViT 尺度理解

这是现在最重要的代码事实。

官方 SHViT-S1 配置：

```python
embed_dim   = [128, 224, 320]
depth       = [2, 4, 5]
partial_dim = [32, 48, 68]
types       = ["i", "s", "s"]
```

官方 `patch_embed` 不是普通 4×4 stride-4，而是连续 **4 个 stride=2 Conv-BN**：

```text
input 256×256
  ↓ Conv s2     C16   -> 128×128   (1/2)
  ↓ Conv s2     C32   ->  64×64    (1/4)
  ↓ Conv s2     C64   ->  32×32    (1/8)
  ↓ Conv s2     C128  ->  16×16    (1/16)
```

然后：

```text
blocks1 : 1/16, C128, type="i"  —— 没有 SHSA
blocks2 : 先 PatchMerging 到 1/32, C224，再执行 stage2 blocks
blocks3 : 再到 1/64, C320
```

因此上一版文档中“SHViT 原生四尺度 stage = 1/4, 1/8, 1/16, 1/32”这个说法需要修正。

准确说法应该是：

> **我们主动从 SHViT 的 patchify stem 中间层取 1/4、1/8 特征，再取 blocks1 输出作为 1/16 特征、blocks2 输出作为 1/32 特征。**

推荐固定四个 tap，不要再做挑层搜索：

```text
F1 = patch_embed 第二个 Conv+ReLU 后      = B×32 ×64×64   (1/4)
F2 = patch_embed 第三个 Conv+ReLU 后      = B×64 ×32×32   (1/8)
F3 = blocks1 输出                         = B×128×16×16  (1/16)
F4 = blocks2 输出                         = B×224×8×8    (1/32)
```

对应：

```python
encoder_dims = (32, 64, 128, 224)
```

### 本地实现时不要重建一套不同名字的 stem

最安全的方式是**保留官方 `patch_embed` 的模块结构与 state_dict key**，只改 forward：

```python
x = img
for i, m in enumerate(self.patch_embed):
    x = m(x)
    if i == 3:       # 第二个 Conv 后的 ReLU
        f1 = x
    elif i == 5:     # 第三个 Conv 后的 ReLU
        f2 = x

x = self.blocks1(x)
f3 = x

# CASAA 在这里作用于 paired f3
...

x = self.blocks2(x)
f4 = x
```

这样官方 `shvit_s1.pth` 中 retained keys 仍可逐个 exact load。

### 必须做 shape smoke

256×256 输入必须精确得到：

```text
F1  (B, 32, 64, 64)
F2  (B, 64, 32, 32)
F3  (B,128, 16, 16)
F4  (B,224,  8,  8)
```

任何一个不一致，先停，不要开始正式训练。

# 3. P0/P1：CASAA@1/16 不能直接声称继承 SHViT 的 QKV 预训练

这是上一版方案中第二个必须纠正的点。

SHViT-S1 的：

```python
types = ["i", "s", "s"]
```

意味着：

- `blocks1`（1/16）是 `type="i"`，其 `mixer = Identity()`；
- 真正的 SHSA 出现在后面的 stage2/stage3，也就是更低分辨率阶段。

所以如果我们把 CASAA 放在 **1/16 F3**，这里**原本没有 QKV attention 参数可继承**。

因此论文和日志里不能写：

> “CASAA@1/16 原位继承 SHViT 的预训练 Q/K/V。”

这是不成立的。

## 3.1 推荐的第一版实现

我仍然建议 CASAA 放 1/16，但做成：

```text
pretrained SHViT blocks1 output F3
            ↓
new CASAA residual branch
            ↓
F3'
            ↓
pretrained blocks2
```

CASAA 自己的 QKV/proj 是新参数，但：

- backbone 仍然是 ImageNet-1K 预训练；
- CASAA 参数非常小；
- 通过 zero-init residual gate，初始化时不破坏预训练 trunk；
- CASAA 输出会继续进入 `blocks2`，因此会同时影响 F3 与 F4。

推荐：

\[
F_3' = F_3 + \beta \cdot \mathcal{A}_{CASAA}(F_3^A,F_3^B),\quad \beta=0
\]

随后：

```text
F3' -> blocks2 -> F4
```

这样论文应写：

> **ImageNet-pretrained SHViT hierarchical trunk + task-specific CASAA insertion**

而不是“CASAA QKV 全部来自 ImageNet 预训练”。

---

## 3.2 不建议为了继承 QKV 把 CASAA 强行移到 1/32

理论上可以把 SHViT stage2 的 SHSA 改造成 CASAA，继承其 attention 参数。

但 1/32 时：

```text
8×8 -> N=64
```

再压缩成 K=16，CASAA 的“高分辨率完整 Query”故事明显变弱，而且计算节省本身也很小。

所以第一版不建议这么做。

---

## 3.3 更不要为了让 stage2 变成 1/16 去改 SHViT stride

例如把某个 PatchMerging stride2 改成 stride1，会导致：

- ImageNet 预训练功能分布改变；
- 后续 receptive field / BN statistics 改变；
- FLOPs 激增；
- “exact pretrained compatibility”失去意义。

这条路线默认否决。

# 4. P0：zero-init 设计不能同时把两层都归零，否则 CASAA 会死锁

上一版建议 `beta=0` 是对的，但实现时有一个容易踩的坑。

SHViT 原始 SHSA 的 `proj` 使用：

```python
Conv2d_BN(..., bn_weight_init=0)
```

也就是说 projection BN 的 gamma 被置 0，以便做残差初始化。

如果你的新 CASAA 又同时：

```text
proj gamma = 0
beta = 0
```

那么：

```text
CASAA branch output = 0
beta.grad = 0
QKV/proj.grad = 0
```

整个新增分支可能永久学不动。

### 推荐只使用一个 zero-init 机制

方案 A（推荐）：

```text
CASAA qkv/proj 正常初始化
external beta = 0
```

这样 step 0：

```text
模型输出与无 CASAA 完全一致
beta.grad != 0
qkv.grad 可能为 0（这是正常的）
```

beta 离开 0 后：

```text
qkv.grad != 0
proj.grad != 0
```

不要再把 CASAA 的最终投影 BN gamma 同时置 0。

### Smoke 必须检查

```text
T0: beta=0 时 base vs CASAA max_abs_diff == 0
T1: beta.grad != 0
T2: optimizer 一步以后 qkv/proj grad 非零且 finite
```

# 5. P0：当前 CASA-CD 的 backbone LR ratio 实际上会被 scheduler 覆盖

这是代码层面最危险的问题之一。

你当前 `models/model/utils.py` 中：

```python
def adjust_learning_rate(...):
    ...
    for param_group in optimizer.param_groups:
        param_group['lr'] = lr
```

也就是说，即使你构建优化器时写：

```python
backbone lr = 2e-5
new modules lr = 2e-4
```

进入第一个训练 iteration 后，scheduler 会把**所有 param group 都改成同一个 lr**。

这会让上一版文档里：

```text
backbone_lr_ratio = 0.1
```

形同虚设。

而你之前已经真实遇到过 DeiT 在较大学习率下 collapse，所以这个问题必须在新主线开始前修掉。

## 5.1 推荐修改

构造 optimizer：

```python
optimizer = torch.optim.Adam(
    [
        {"params": backbone_params, "lr": args.lr * 0.1, "lr_scale": 0.1, "name": "backbone"},
        {"params": new_params,      "lr": args.lr,       "lr_scale": 1.0, "name": "new"},
    ],
    lr=args.lr,
    betas=(0.9, 0.99),
    eps=1e-8,
    weight_decay=1e-4,
)
```

scheduler：

```python
base_lr = ...   # poly + warmup 的基础 lr
for pg in optimizer.param_groups:
    pg["lr"] = base_lr * pg.get("lr_scale", 1.0)
```

日志必须同时打印：

```text
LR/base=...
LR/backbone=...
LR/new=...
```

### 必须做 201 iter dry-run

至少验证：

```text
iter 1
iter 100
iter 199
iter 200
iter 201
```

都满足：

```text
lr_backbone / lr_new == 0.1
```

否则禁止正式 80K。

# 6. P0/P1：SHViT 是 BatchNorm-heavy，Siamese forward 最好一次拼成 2B

SHViT 大量使用 `BatchNorm2d`。

如果共享 backbone 按下面方式顺序跑：

```python
fa = backbone(A)
fb = backbone(B)
```

训练时 BN running statistics 会先被 A 更新一次，再被 B 更新一次；虽然共享参数，但 forward 顺序并不完全对称。

对于二时相共享编码器，更干净的方式是：

```python
x = torch.cat([A, B], dim=0)       # (2B,3,H,W)
...
fa, fb = torch.chunk(x, 2, dim=0)
```

在 CASAA 之前可一直用 2B 单路 shared forward：

```text
[A;B]
  ↓ shared patch_embed
  ↓ capture F1/F2
  ↓ blocks1
  ↓ split A/B
  ↓ CASAA pair
  ↓ concat back to 2B
  ↓ blocks2
  ↓ split F4
```

好处：

- BN 同一批次同时看到 A/B；
- 时相顺序对 running stats 的影响更小；
- shared Siamese 语义更干净；
- GPU 上也通常比两个独立 forward 更高效。

### 注意

CASAA 前后的 split/concat 必须严格保持样本对应关系：

```text
[0:B]   = A
[B:2B]  = B
```

不要在这里做任何 shuffle。

# 7. P0：当前 ToTensor 会把 6 通道整体反转，等价于把 A/B 也交换

当前 CASA-CD：

```python
img = concat(pre_BGR, post_BGR)  # [Bpre,Gpre,Rpre,Bpost,Gpost,Rpost]
```

而 `ToTensor()` 里：

```python
image = image[:, :, ::-1]
```

对 6 个通道整体反转后变成：

```text
[Rpost,Gpost,Bpost,Rpre,Gpre,Bpre]
```

也就是说：

- 每个影像内部确实转成了 RGB；
- 但 A/B 时相顺序也被交换了。

对于二值变化检测，标签本身通常对 A/B 交换不敏感；而训练增强里还有 `RandomExchange()`，所以历史结果未必受到明显伤害。

**但现在不能在新主线里无意识地“顺手修复”这个行为。**

因为一旦改成：

```python
pre = pre_BGR[..., ::-1]
post = post_BGR[..., ::-1]
concat(pre_RGB, post_RGB)
```

你的新模型就改变了历史 ChangeViT 协议的一部分。

为了保持协议一致，第一轮 CASA-STR **保留现有数据协议**，但加一个诊断日志：

```text
[DATA-CHANNEL-CONTRACT] legacy_6ch_reverse=True
```

并新增一个 unit test，明确验证张量中的前 3 通道来自哪一个时相。

如果以后决定修复，则必须：

> 把它作为一次“全新数据协议版本”，所有 A0/A1/A2/M1 和强基线都在该版本下重新跑，不能混用旧结果。

# 8. P0：不要把 STR-RepNet 的训练器一起搬过来

你需要从 STR-RepNet 迁移的是：

```text
TemporalRep1x1 / MultiScaleTAR
RepDW3 / RepPW1x1 / RepPairFuse1x1
DCRDecoder
switch_to_deploy / fold equivalence
```

**不要迁移 STR-RepNet 的训练协议。**

因为 STR 历史项目与 CASA 当前固定协议不同。

CASA-CD 必须继续：

```text
1-channel probability output
BCE + Dice
Adam 2e-4
poly + warmup
80K
seed 16
256×256
```

特别注意输出头：

```python
head = nn.Conv2d(dim, 1, 1)
prob = torch.sigmoid(logits)
```

因为当前 `BCEDiceLoss` 用的是 `binary_cross_entropy`，不是 `BCEWithLogitsLoss`。

不要直接照搬 STR 的：

```text
2-class logits + CE/Lovasz
```

否则实验已经不是同协议比较。

# 9. P1：导师原始“空间异构重参数化”和当前 Run2 DCR 不是完全同一个实现

导师原始文档第二页给的是：

```text
DW5×5
DW3×3
DW3×3 dilation=2
DW1×5
DW5×1
identity
        ↓ fold
single DW5×5
```

而 STR-RepNet 当前最成熟的 Run2 DCR 主要使用：

```text
RepDW3:
DW3×3 + DW1×3 + DW3×1 + alpha·I
        ↓
single DW3×3
```

以及：

```text
RepPW1x1
RepPairFuse1x1
```

所以 CASA-CD 第二创新点要明确选择哪个版本。

## 9.1 本轮建议

**优先迁移 STR-RepNet Run2 已经验证稳定的 TAR + DCR。**

原因：

- 已经过多轮 fold 等价性验证；
- 后续 Run3–Run10 已经证明继续搜索大量 rep 分支并没有稳定收益；
- 现在的主要变量应该是“CASAA + STR 是否在新轻量 backbone 上成立”，而不是重新打开空间 rep 搜索。

因此论文可以写：

> 源于导师原始“时空结构重参数”思想，具体实现采用已经验证过的 temporal algebraic re-parameterization 与 deploy-equivalent cross-scale decoder。

但不要把 Run2 的 DW3 分支写成导师文档里的完整 DW5/空洞/1×5/5×1 组合。

**代码是什么，就写什么。**

# 10. P1：CASAA 的 change score 不能再完全照搬旧固定 Kc=32 的叙事

旧 CASA 已经提供了一个重要负面证据：

```text
固定 Kc=32
```

与不同影像真实变化 patch 数量不匹配，尤其 SYSU 的变化密度跨度很大。

所以新 `casaa_hier.py` 不要把：

```python
K = 64
Kc = 32
Kb = 32
```

写死在代码内部。

至少要做成：

```python
keep_ratio
change_share
```

配置项，并写入 checkpoint / manifest。

### 第一轮仍可以固定 0.5

为了避免重新做大规模超参搜索，第一轮主实验可以预注册：

```text
N=256
K=64
change_share=0.5
Kc=32
Kb=32
```

但论文里必须把它称为**固定预算设计**，不能暗示它已经自适应匹配变化面积。

如果这一版最终失败，而 router audit 再次显示 quota mismatch，那么下一次允许的正交改进应该是：

> **统一、跨四数据集的 adaptive quota 机制**

而不是在 CDD/LEVIR/SYSU/WHU 各自调 Kc。

绝对不要形成：

```text
CDD Kc=16
LEVIR Kc=24
SYSU Kc=48
WHU Kc=20
```

这种 dataset-specific tuning。

# 11. P1：Full Query 的定义必须写清“空间位置完整”，不要混淆“通道完整”

CASAA 的核心约束是：

```text
N 个空间 query 位置全部保留
```

即：

```text
16×16 -> 256 query locations
```

不能删掉 query token。

但这并不要求 Q 一定使用全部 128 个通道。

如果后续为了贴合 SHViT 的 partial-channel attention，考虑：

```text
部分通道做 CASAA
其余通道 bypass
```

仍然可以满足“Full Query positions”。

不过为了首轮归因最干净，我建议第一版先用：

```text
C=128 full-channel CASAA
```

因为参数和 FLOPs仍然很小，而且可以最大程度复用 CASA 现有 `CASAAAttention` 的正确性逻辑。

以后如果 FLOPs/latency 成为瓶颈，再做 partial-channel 版本；不要第一轮同时改 backbone、attention channel partition 和 routing。

# 12. P1：CASAA 不能只算 attention matmul FLOPs，routing 也是推理图的一部分

当前 `deterministic_density_assign()` 里面存在：

```text
subsample pairwise similarity
TopK density
center selection
all-token → center similarity
argmax assignment
one-hot / aggregation
```

这些操作都在**推理期真实发生**。

所以论文只能写：

> attention interaction 从 \(O(N^2)\) 降为 \(O(NK)\)

不能写：

> 整个 CASAA 从 \(O(N^2)\) 变成 \(O(NK)\)

更不能只用：

```text
QK^T / AV FLOPs
```

就声称整个模块省了 75%。

compressed attention matmul theoretical FLOPs
routing similarity theoretical cost

在 RTX 5090：

# 13. P1：fvcore 对动态 TopK / sort / indexing 可能漏算，正式 FLOPs必须双口径

当前 CASA `measure_flops()` 会打印 `unsupported_ops`，但对 CASAA 这种动态 routing，单独一个 fvcore 数字不够可靠。

+ CASAA routing/manual attention supplement

# 14. P0：A3 Plain 与 M1 Full STR 的初始化必须严格可比

结构重参数化消融的核心要求是：

```text
A3: CASAA + plain deploy topology
M1: CASAA + rep training graph -> same deploy topology
```

如果两者共同模块的初始权重不同，那么单 seed 下 `M1-A3` 会混入随机初始化差异。

问题在于：

> 构造额外 aux branch 本身会消耗 RNG，即使你随后把 aux 权重置 0，也可能让后面构造的共同层拿到不同随机数。

STR 后续实验里已经遇到过这类 RNG 问题。

## 14.1 推荐做法

模型构造完成后，做一次 `common-state hash` 审计：

```text
CASAA qkv/proj
TAR main branch
DCR main branch
head
```

A3 与 M1 必须逐 tensor 相同。

最稳妥的方法之一：

```text
1. 构造公共 core
2. 固定初始化公共 core
3. 最后再 attach zero-init rep auxiliary branches
```

或者：

```text
统一 deterministic reset_common_parameters(seed=16)
```

对所有共同模块按固定名字顺序重新初始化。

### smoke 判据

如果 aux 分支的初始输出为 0，则：

```text
A3 train-graph output
≈
M1 train-graph output at step0
```

应在同一随机输入上做到非常小误差，理想情况下 bitwise identical。

# 45. 失败时怎么解释，避免继续模块堆叠

## 情况 A：A0 四数据集就明显偏低

说明：

> 主要问题在 truncated SHViT 表征能力/尺度 tap，而不是 CASAA 或 STR。

处理：

```text
先重新评估 backbone
不要让 CASAA/STR 去补一个明显过弱 backbone
```

## 情况 B：A0 强，但 A1/CASAA 不提升

说明：

> CASAA 的 placement / routing / compressed context 没提供额外判别信息。

优先查：

```text
score quality
Kc quota mismatch
attention mass
change/background cluster purity
```

不是立刻加 edge head。

## 情况 C：A1 强，但 M1 不提升

说明：

> 第二创新点的训练期重参数化在新 backbone/decoder 下没有稳定优化收益。

查看：

```text
A2-A0
M1-A1
branch gamma/norm
Recall/Precision tradeoff
```

如果再出现 STR 历史多轮的“Precision↑ Recall↓、F1不变”签名，就应停止继续 rep branch 搜索。

## 情况 D：M1 指标好但 >5M

此时才做预算优化。

优先：

```text
降低 STR dim
CASAA partial-channel
删无效层
```

不要一开始为了追 2M 把表征能力砍掉；现在硬门槛是 ≤5M。
