## 2. 唯一主方案 R4-FET1：形状、公式、数据流、论文定位

### 2.1 输入、插入点与实现边界

- **不触动** TinyViM、CAACP 的 `no_grad` score、Stage3 2×2 cell、四个 TARStage、DCR 内部块、`head`、Loss。
- `CASATViMSTRNet.forward()` 已取得 `f1a, f1b ∈ ℝ^{B×48×64×64}`，同源于共享编码器 `encoder.norm0`。该节点正是 Diag1 `L01b_norm0`，不是未经验证的 patch-embed 旁路。
- 令 `P=f1a`、`Q=f1b`、`D=|Q−P|`；`X=[P,Q]∈ℝ^{B×96×64×64}`、`Z=[P,Q,D]∈ℝ^{B×144×64×64}`。
- 旧路径 `t_i=TAR(P_i,Q_i)`、`R=DCR(t1,t2,t3,t4)∈ℝ^{B×96×64×64}` 保持完全不变。新路径在 `R` **已经由 refine 产生后**做一次残差相加：`R' = R + T(P,Q)`，然后保持 `head(R')→bilinear→sigmoid` 不变。
- **不在 refine 前相加**：前置会改变 RepLocalBlock 中 SiLU 非线性与现有 DCR 训练路径，不能把来源影响与解码容量影响分开；后置仅检验浅层证据能否补足当前决策特征，因果解释更窄。

### 2.2 训练期精确定义（所有卷积 stride=1、padding=0、groups=1）

定义 **同一个 FET1 算子内部** 的两路线性表征，绝不引入归一化/激活/新 loss：

\[
U=W_{pq}*[P,Q]+b_{pq},\quad
V=W_{\Delta}*|Q-P|,\quad
T(P,Q)=\gamma(U+V),\quad R'=R+T(P,Q).
\]

- `W_pq∈ℝ^{96×96×1×1}`, `b_pq∈ℝ^{96}`；`W_Δ∈ℝ^{96×48×1×1}`，**无 bias**；`γ∈ℝ` 为可学习 scalar。
- 初始化：`W_pq,b_pq` 用隔离的局部随机数生成器进行标准卷积初始化（具体种子在代码写常量并记日志）；**`W_Δ=0`、`γ=0`**。主分支输出在初始化时非恒零，保证 `∂loss/∂γ` 可能非零；aux 初始输出严格零，γ 未打开前 aux 参数梯度为零，打开后能学习。`b_pq` 必须属于 U，不能另置一个输出 bias 再加两次。
- 在 `gamma=0` 时不使用 `if gamma==0: return R` 的动态图捷径；保持计算图，保证 gate 有梯度。头仍是 `Conv2d(96,1,1)`。

建议新类 `FineEvidenceTap1x1(nn.Module)`（`models/model/str_fine_tap.py`）：

```python
class FineEvidenceTap1x1(nn.Module):
    def __init__(self, in_ch: int = 48, out_ch: int = 96, deploy: bool = False): ...
    def forward(self, P: torch.Tensor, Q: torch.Tensor) -> torch.Tensor: ...
    @torch.no_grad()
    def get_equivalent_kernel_bias(self) -> tuple[torch.Tensor, torch.Tensor]: ...
    @torch.no_grad()
    def switch_to_deploy(self) -> 'FineEvidenceTap1x1': ...
```

`CASATViMSTRNet.__init__(..., fine_tap=False)` 新增开关，**默认 False，旧路径完全兼容**；`forward` 精确改动为：

```python
feats = self.tar([f1a, f2a, f3a, f4a], [f1b, f2b, f3b, f4b])
x = self.decoder(feats)  # 原始 DCR.refine 输出 [B,96,64,64]
if self.fine_tap:
    x = x + self.fine_evidence_tap(f1a, f1b)
logits = self.head(x)  # 旧 head，不新增末端头
```

### 2.3 与仅有的两个创新的关系

- **创新一 CAACP-SS2D 不变**：低频分支只在 Stage3 最后一个 TViM 上做变化感知 2×2 cell 上下文聚合、β=0 预训练兼容；FET 不修改 score、池化规则、dense scan 或双时相共享权重。
- **创新二 STR 的 DCR 细尺度证据保持路径**：FET 是 DCR 输出残差接口的一条**线性可折叠细尺度时相代数旁路**；训练将 `P,Q,|Q−P|` 分路表达，部署折为一次 1×1 卷积。论文中把它写成“STR 解码路径上的 fine-scale evidence preservation”，**不独立命名第三个核心创新、不声称新的注意力理论或 token 聚类方法**。
- **区别于 E2 FRH**：E2 在已有 `R` 上做 128² 高分辨率处理，不能恢复未进入 `R` 的时相特征；本方案新输入直接取 `norm0(A/B)`。**区别于 E5 FS-TAR**：E5 修改 Stage1 TAR 已有时相核，但随后仍经历 DCR 融合；本方案绕过其后续尺度融合的抑制（若真实存在）。

### 2.4 必须能被数据推翻的假设

`[H-FET]` **未被 M1 命中的 SYSU small GT 对象**，在 `L01b_norm0` 的 train-only probe 仍保留独立于 DCR 决策的正向局部 margin；原生特征残差通路学习后，能同时增加 small pooled Recall/Hit@25，**不以增加 <256px 未匹配预测碎片为代价**。

失败证据 = 前测显示漏检对象与背景伪目标不能分开，或完整 Run4 中 recall/Hit 无达标提升，或 ObjPrecision/中大目标/CDD/WHU 触发守门下降。失败时**终止 FET 系列**，不追加 1/8、3×3、rank/loss 等第二层补丁。

## 3. Deploy 参数预算与 FLOPs 精确核算

### 3.1 训练图、部署图逐项算账（D=96，C=48）

| 部件 | 参数公式 | 训练图新增 | deploy 新增 |
|---|---:|---:|---:|
| `pq` 1×1：96→96，bias=True | `96×96+96` | **9,312** | —（并入 fused） |
| `absdiff` 1×1：48→96，bias=False | `96×48` | **4,608** | —（并入 fused） |
| `γ` scalar | `1` | **1** | **0**（吸收入卷积） |
| **合计** | | **13,921** | — |
| **fused 1×1：144→96，bias=True** | `96×144+96` | — | **13,920** |
| 原 M1（Diag1 D0） | | **5,084,017** | **4,880,190** |
| **R4-FET1 总量** | | **5,097,938** | **4,894,110** |
| **部署剩余余量** | `5,000,000−4,894,110` | — | **105,890** |

**硬结论：R4-FET1 满足 ≤5,000,000；不是“约等于 5M”，而是精算 4,894,110。** 以上数值是假设其它 M1 部件完全同构且无重复注册新 `nn.Parameter`；最终以 `sum(p.numel() for p in model.parameters())` 的**实际 deploy 图**为准，`assert n==4_894_110 and n<=5_000_000`。训练图“可训练参数总数”尚需在 RSML-3 实测：`+13,921` 必须精确；M1 编码器在本方案中仍按原训练协议可训练，**不要把冻结 backbone 的其它项目口径套用到这里**。

**3×3 原案直接否决**：单个 `Conv2d(144,96,3,bias=True)` 参数 `144×96×9+96=124,512`，总 deploy `4,880,190+124,512=5,004,702`，**超 5M 共 4,702**。不能先做 1×1+DW3 再把折叠后 **124,512** 误写为 depthwise-separable 的部署参数：若要求最后**一个常规 Conv3×3**，就必须按 124,512 算。最终降级/固定方案就是本节的 **1×1**，无需动骨干/降低 D。

### 3.2 折叠后结构：只有一个**额外**的卷积，不宣称全网络只剩一层卷积

令 `W_pq = [W_P,W_Q]`，`W_Δ` 与其拼接为 `W_Z∈ℝ^{96×144×1×1}`；

\[
W_{\mathrm{fused}}=\gamma[W_P,W_Q,W_\Delta],\qquad
b_{\mathrm{fused}}=\gamma b_{pq}.
\]

部署：`T(P,Q)=Conv1x1(cat(P,Q,abs(Q−P)); W_fused,b_fused)`；原 DCR、TAR 仍按自身 rep 方法折叠。**FET 这条新分支训练的两条线性卷积+gate 严格折叠为一条 1×1 Conv**，其输出与已有 `R` 相加。由于 `R` 经多级 SiLU、且 `Z` 是独立输入，**不能把该卷积进一步并入已有 `decoder.refine.pw` 或 `head` 而同时保持结构与函数不变**；部署总图具有“一条额外的单卷积残差支路”，不应误表述为“整个 DCR 没增加推理支路”。这个真实开销已计入硬预算。

融合计算必须 FP64 拼核、**只在最后一次赋给 deploy Conv 时 cast 到 FP32**；移除旧 `pq/absdiff/gamma` 参数（`state_dict` 中不得残留）；部署入口可调用两次，第二次必须幂等。

### 3.3 256×256 FLOPs 预测与测量纪律

- FET1 作用网格 64×64，一次 fused Conv 的乘加数（fvcore convention，1 MAC=1 FLOP）= `64×64×144×96` = **56,623,104** = **0.0566231 G**。两支训练期卷积乘加之和相同；`abs(Q−P)` 是 `48×4096=196,608` 个元素级运算量（不混入卷积 MAC）；γ 乘和 `R+T` 另外各 `96×4096` 个元素级操作。
- 若 fvcore 不计这些 elementwise ops，预期 deploy **≈2.6747+0.0566231=2.7313 G**；这是**预测，不是实测正式 FLOPs**。报告必须同时列 `[DEPLOY-FLOPS]`、`unsupported_ops`，并与同工具/输入/算子版本的 M1_R4CTRL 进行差值对照。`unsupported_ops>0` 时注明“fvcore 支持算子计数”，不得称全模型精确总 FLOPs。
- 训练前后都运行 `models/train.py::measure_flops`（`fvcore.nn.flop_count(model,(pre,post,label))`，batch=1，2×3×256²）；对比训练图和 `switch_to_deploy()` 后，记录参数、fvcore FLOPs、unsupported ops 集合/数量。FET 的 MAC 还应由手工公式交叉核验。

## 4. 零初始化、预训练继承、epoch-0 等价性与折叠证明

1. **结构不改旧参数**：构建顺序为 `encoder → head → tar → decoder → fine_evidence_tap`。新模块**必须最后构造**，且其卷积随机初始化通过 `torch.random.fork_rng` / 独立局部 `torch.Generator` 隔离全局 RNG。不要改 head/TAR/DCR 构造顺序或开启 FRH/FS-TAR；原 TinyViM `model_ema` 完全加载。
2. **epoch-0**：`γ=0`，故 `T=0`，`R'=R+0=R`；预期 `M1_R4CTRL` 与 `R4_FET1` 在相同原始种子、同一预训练文件、相同非 FET 权重下，对固定 FP32 输入的前向**逐位相同**：`torch.equal(y0,y1)`，`max_abs==0.0`、`binary_disagreement==0`。这不是只要求 `allclose`。
3. **公共权重位同**：用相同 `torch.manual_seed(16)` 分别实例化两个模型，逐 `state_dict` 对比所有旧键：旧键集合完全一致、旧键每一 tensor `torch.equal`；唯一新键只允许 `fine_evidence_tap.*`。额外核验 `torch.get_rng_state()` 在两种模型构造后完全一致（CUDA RNG 状态如模型均在 CPU 构造后再搬 CUDA也应一致）。否则禁止训练，先修复初始化 RNG 污染。
4. **数学折叠**：卷积线性分配律给出 `γ(W_pq*[P,Q]+b+WΔ*|Q−P|)=(γ[W_pq,WΔ])*[P,Q,|Q−P|]+γb`；abs 是**卷积之前的输入特征构造**，不是企图把 abs 非线性吸入卷积。γ 训练后可正可负，不施加 sigmoid/tanh；无 BN/SiLU 于 FET 分支内部。
5. **非平凡等价性**：除了 γ=0 trivial smoke，必须人为赋 `γ=0.3`、`WΔ` 非零及非零 bias，对 FET 局部 FP64 代数 `max_abs<1e−10`，FP32 子模块 `max_abs<2e−5`，整个 CASA 模型随机 batch `max_abs<2e−4`、**二值 disagreement=0**；真实 batch=16 亦 0。训练完成后对**正式 best checkpoint** 再跑同样 hard gate（不能拿初始化 smoke 代替训练后证据）。
6. **数值控制**：依照 `models/train.py::test_best_strfusion`，折叠检查期间 `cudnn.allow_tf32=False`、`cuda.matmul.allow_tf32=False`、`cudnn.deterministic=True`，严格 `p>0.5`。若任一像素翻转，按 Diag1 对 A2 的纪律记 **FAIL**，**不能用 1/1,048,576 很少放行**。记录 train/deploy 两份概率和阈值附近最小 margin 以定位刀锋像素；不得改评估阈值。
7. **预训练加载规则**：新 FET 参数不是 ImageNet 预训练，只有原 backbone 从 `tinyvim_s_1000e.pth:model_ema` 继承。打印 `[PRETRAIN-LOAD] retained=... worst_diff=0` 与 exact-loaded keys 哈希；比较 M1_CTRL、FET 的 backbone 同名权重相等。**绝不能把原 Run1 `best_F1=*.pth` 当 Run4 初始化**。

## 6. 预注册实验设计（≤4 变体，实际仅 2）

### 6.1 变体矩阵、唯一变量和预算

| Run4 变体 | `fine_tap` | 其它结构 | 四库正式训练 | 用途 |
|---|---:|---|---|---|
| **M1_R4CTRL** | **0** | CAACP rank/current=1、TAR/DCR full、D96、FRH=0、FS-TAR=0 | **各 80,000 optimizer updates，从 ImageNet 预训练启动** | **必要的同期唯一变量对照**，排除代码/80K 实施校正差异 |
| **E6_FET1** | **1** | 与 CTRL 完全相同，**仅新增 §2 的 1×1 FET** | **各 80,000 optimizer updates，从同一 ImageNet 预训练启动** | 唯一正式主实验 |

**不设** FET 1/8、3×3、FRH+FET、FET+FS-TAR 训练组；γ=0 的模型对拍是**smoke**，不是第三个 80K 变体；Diag1 的 probe/preflight 不是正式训练组。四个数据集每组一次、seed16，合计 **8×80K**。原 Run1/M1 作为历史参考，不替代本轮 CTRL 的同期对照。

固定：`BCE+Dice / Adam(lr=2e-4, betas=(0.9,0.99), wd=1e-4) / backbone_lr_ratio=0.1 / poly 0.9 + 200iter warmup / batch=32 / 256×256 / seed=16 / test-as-val，选 best test F1 / p>0.5`；相同 dataset train/test list 哈希、相同增强、相同预训练文件哈希；除 FET 外禁用额外 teacher / score 调优 / EMA。

### 6.2 必须先修复的 P0：`max_steps=80000` 目前**不是精确训练步数**

源码 `models/train.py:583–584` 使用 `max_epochs=ceil(max_steps/len(loader))`，`train_epoch` 跑完整 epoch；`models/model/utils.py:72` 又以 `len(loader)*max_epochs` 作为 poly 分母。按服务器数据集列出的 train 样本和 `batch=32,drop_last=False`：

| 数据集 | train 数 | 每 epoch batch | 当前代码实际更新数（推导） | 比 80K 多 |
|---|---:|---:|---:|---:|
| CDD | 10,000 | 313 | 80,128 | 128 |
| LEVIR | 7,120 | 223 | 80,057 | 57 |
| SYSU | 12,000 | 375 | 80,250 | 250 |
| WHU | 5,947 | 186 | 80,166 | 166 |

**裁决：Run4 实现 80,000 步严格封顶，并在相同校正后的训练器上同步重训 CTRL 与 E6；不把历史 M1 与 E6 的差异称为唯一结构差异。** 具体做法：`train_epoch(..., remaining_steps)` 在第 `remaining_steps` 次 update 后 `break`，返回 `executed_steps`；`cur_iter += executed_steps` 而不是固定 `max_batches`；`cur_iter>=80000` 必须退出；poly 的分母固定 `args.max_steps=80000`，原 warmup200 不变；`[ACTUAL-OPT-STEPS] 80000` 必须进入最后 TEST 区块。**这是让实现满足既定协议的 P0 修正，而非优化训练策略；若决定保留历史整 epoch 口径，则不能再声称“精确 80K”，必须重新进行 protocol 裁决，且不能与严格80K实验混比。**

断点恢复：仅允许**同一路径同 variant 的中断恢复**，不允许跨变体 checkpoint 初始化。`last.pth` 在已完成 epoch 边界保存 optimizer、`actual_steps`、PyTorch CPU/CUDA、NumPy、Python RNG；恢复后校验 `arch`/数据哈希/预训练哈希/模型键集合；用小规模 **uninterrupted vs resume** 对拍 3–6 步（参数/optimizer/LR 轨迹相同）验收。当前代码仅记录 epoch/optimizer 而未保存 RNG 状态，**不能宣称已有精确续跑能力**。若恢复对拍失败：停机，保留日志/权重，在新的**独立**目录从头训练，不覆盖历史文件。

### 6.3 预注册目标：三层裁决，不以单项漂亮数字替代论文目标

**层 A：P0 有效性**：所有四库 E6：deploy ≤5M；train/deploy 实测双 batch 二值 disagreement=0；日志 TEST 块完整、步数=80,000、6 指标/FLOPs 齐全；任意失败 → **INVALID**，不讨论 F1。

**层 B：机制命中（SYSU 主判，以下均是预注册通过线，不是假称已有结果）**：

| 指标（SYSU 4连通，n=364 small） | Diag1 M1 历史值 | E6 最低要求 | 与 CTRL 同期要求 |
|---|---:|---:|---|
| small pooled pixel Recall | 0.1974 | **≥0.2474（+5.0pp）** | **≥CTRL+0.0500** |
| small Hit@25 | 0.1896 | **≥0.2396（+5.0pp）** | **≥CTRL+0.0500** |
| ObjRecall（IoU≥0.10） | 0.7674 | **≥0.7774（+1.0pp）** | **≥CTRL+0.0100** |
| ObjPrecision（IoU≥0.10） | 0.5320 | **≥0.5320** | **不得低于 CTRL** |
| 未匹配 <256px 预测域 | 2430 | **≤2430** | **不得高于 CTRL** |
| SYSU F1 / IoU | 83.47% /71.63% | **F1≥83.47、IoU 同方向** | **F1≥CTRL** |

如历史基准与同期 CTRL 因训练步数修正发生差异，则**绝对门槛与同期增量门槛必须同时满足**，不得选择更容易的一个。对象组 n<100 的 tiny_1_15、tiny_16_63 只作诊断；WHU small n=79 不执行显著性声称。若小目标召回增益来自新 FP，判定 **机制 FAIL**。

**层 C：跨库守门与最终硬目标（所有正式 TEST）**：

| 数据集 | Run1 M1 历史 F1（%） | **E6 不退守门（%）** | **论文硬目标 F1（%）** |

**`PAPER-TARGET-PASS` 当且仅当** P0 全过、机制过门、四库 F1 **同时**达到 CDD 98.00/LEVIR 92.50/SYSU 85.00/WHU 95.00，并满足对照/守门；IoU 与 F1 同方向（相同混淆矩阵上 `IoU=F1/(2−F1)`，F1 按比例值计算）。其余即使 SYSU small 指标改善，也只能记 **MECHANISM-PASS / PAPER-TARGET-FAIL**，不能写“实现四库目标”。四库单 seed 结果不声称统计普适性。

### 6.4 FAIL 决策树（禁止失败后继续堆模块）

1. `P0 INVALID` → 修复相应代码/折叠/协议，先重跑 smoke + dry-run；**未达 80K 的训练不能入结果表**。
2. `SYSU small Recall<0.2474` **或** `Hit@25<0.2396` **或**同期增量不足 5pp → **FET 机制否决**，停止 1/4 tap 线；不试 1/8/3×3。
3. small 指标上涨，但 ObjP<0.5320、同期 ObjP 下降或 <256px unmatched FP 上升 → **伪变化放大而非证据恢复**；停止该线，转向 Diag1 D1 的 FP 空间画像分析（只诊断不加头）。
4. SYSU 命中但 CDD<97.18 或 WHU<95.07 或任一同期 CTRL 下滑 → **跨数据集守门 FAIL**；停止论文主方案，不以 SYSU 单库成功宣称普适改进。
5. 全守门达成，但任一硬目标未到 → `PAPER-TARGET-FAIL`；保留负结果和机制分析，不通过阈值/loss/seed 搜索挤分。
6. 全部达成 → 冻结 Run4 结构，正式报告 6 指标、train/deploy 参数量、FLOPs、FET γ、对象统计；再考虑论文撰写，不追加模块。

## 10. 对研究预期的管理：最小补证，给出可执行上界和硬阈值

### 10.1 缺失信息的唯一核心：conditional complementarity

**结论等级：`H5 SUPPORTED`，但 `R4-FET expected improvement = INCONCLUSIVE`。** Diag1 的 `L01b_norm0` small margin=0.0779 是**全体 GT small 对象**的均值；不能推出**M1 漏检对象**也有剩余浅层辨识度。用户要求在不足以支持结构改动时不得硬造方案，因此**新 80K 的启动必须由下面一次前测批准**。方案本身唯一且已精确预注册，不再同时设计多模块。

### 10.2 已有 checkpoint/权重、统计单位、预算上界

- 固定 M1：`/share_datasets/yqwang/checkpoints/CASA-CD/CASA-TViM/Run1/M1_FULL/SYSU-CD-256/best_F1=0.8347.pth`，报告 SHA256 `45d688a01af22fe22521f4dfb4579e80827ddcaa886e07bafc778fc288731457`。
- 固定 probe：`/home/yqwang/outputs/CASA-CD/diagnostics/TViM-TinyLoss-Diag1/D3_concat/M1_FULL/probe_L01b_norm0_PROBE_ONLY.pth`（由 Diag1 原 probe train-only 拟合）。**不重新拟合、不访问其它 checkpoint、不修改任何模型参数**。使用 `tvim_diag_common.set_eval_numerics()` 和同一 `make_loader(SYSU,test)`，4000 test 各仅一次模型 forward；`p>0.5`、4 连通、原生256²，与 Diag1 一致。
- 对每个 1–255px GT small 对象 `g`：利用原 M1 的 `p>0.5` 得到 `Hit@25(g)`；若 `<25%`，归为**missed-small**（约 295 个是由 364 与 Hit=0.1896 推出的近似数量，**非新的实测统计**）。计算冻结 L01b concat probe 概率场在 GT 对象内部与“外侧 4px 环带、剔除所有 GT”的 mean 差：`margin_probe(g)`，使用 Diag1 D3c 完全相同的 `F.interpolate(...,bilinear,align_corners=False)` 和 ring 定义。
- 对 M1 **未匹配预测对象**（loose IoU≥0.10 的一次性最大权重匹配之后仍未匹配，面积 1–255px，Diag1 为 2430 个）计算同样的 probe“预测对象内部－外侧4px无GT环带”margin，作为**FP-like 对照**。这只用于检验可区分性，不能混写为 ObjPrecision。
- 固定阈值 `margin_probe≥0.03`（预注册诊断阈值，**不是分割阈值**，不得参与 E6 推理）。定义 `rescue_rate = missed-small 中达到该 margin 的对象比例`，`fp_like_rate = unmatched-small FP 中达到该 margin 的比例`，`gap = rescue_rate−fp_like_rate`。bootstrap=1000，**按图像抽样**计算 gap 95%CI，不按像素当独立样本。
- **PASS 当且仅当**：`n_missed_small>=100`、`n_fp_like>=100`、`rescue_rate>=0.20`、`gap>=0.10`、`gap bootstrap 95%CI 下界>0`。任意不满足判 `INCONCLUSIVE/FAIL→NO_80K`。`gate.json` 同时记录 4000 张、probe checkpoint SHA、M1 SHA、list SHA、对象分组、阈值、版本号 `run4_fet_preflight_v1`。
- **资源上界**：GPU0 独占执行、单次全 SYSU test forward 和 1000 次按图 bootstrap；以 Diag1 D3c 实测约 5 min 为参考，**本次预算上限 10 min GPU 时间**。超时/挂起计 `PRECHECK-INCOMPLETE`，停止而非扩到无限诊断。输出独立目录，不覆盖 Diag1。

**解释边界**：preflight PASS 只说明“已有 shallow probe 能在部分 M1 漏检对象上区别于伪阳性”，**不是**“FET 训练必达 85% SYSU”。它把 H5 转为一个有门槛的、可检验的 R4 结构假设。preflight FAIL 则直接停止新结构，回到现有 D1 `object_level.csv` 和 D3 的 FP 画像做下一次**新的预注册**，而非继续 1/8/3×3 搜索。
